# 视频工作流升级与实测交接

日期：2026-09-08；分支：`codex/visual-understanding`。本文件区分工程完成与语义质量；测试中的失败同样保留。

## 实现

保留 FastAPI、Worker、SQLite、FAISS/BM25、React 与现有上传播放链路。复用 [Qwen 官方有序帧视频协议](https://www.alibabacloud.com/help/en/model-studio/vision)与 [PySceneDetect](https://www.scenedetect.com/docs/latest/api.html) 的 AdaptiveDetector；没有整体引入 VideoRAG/VideoDB 等服务。

1. 新上传默认先转写，再进入 VISUALIZING。先检测镜头边界，让短镜头独立分析；长镜头再按默认 12 秒窗口、相邻重叠 2 秒分析。每次请求最多 24 张 640 像素宽图片，生成带开始/结束时间的事件。当前视觉版本为 `sequence-v3`。
2. 90 秒以内的概括/摘要使用覆盖全片的画面序列、事件和转写。概括不受检索命中门槛限制。更长视频概括使用完整事件材料，不能声称最终模型直接看过全片原始画面。
3. 细节问答用事件定位片段，向前保留 4 秒上下文，回看最多 8 秒、24 帧；采用逐图紧邻绝对时间戳的图片序列，改进图像和引用的对应。事件文字只负责定位；具体回答和核验直接读取原始画面与相关语音，避免旧 caption 措辞锚定结果。
4. 语音是独立证据。视觉请求不发送音轨；ASR 失败/无语音允许纯视觉处理，并显示告警。噪声转写不能被扩写为确定主题。
5. 视觉结果保存版本和分析时间；摘要缓存包含分析修订与视觉模型。重新分析开启空白会话；旧会话保留并标注材料已更新，新回答不继承旧事实记忆。
6. 旧视频默认页直接提供“开始音画分析”。分析期间禁用摘要/问答；缺少新版视觉结果返回 `VISION_ANALYSIS_REQUIRED`，不伪装成无依据拒答。

## 修复的具体缺陷

| 缺陷 | 修复与证据 |
| --- | --- |
| 概括仍被空检索拦住 | 全局问题直接使用时间线；空检索回归测试覆盖概括与场景顺序 |
| 单帧物品罗列丢失动作 | 连续重叠窗口、有序帧输入、按问题回看 |
| 长窗口事件上限挤掉短镜头 | 复用 PySceneDetect 切分；Sintel 16.5–17.5 秒战斗镜头成为独立输入窗口 |
| 回看从动作结果附近开始，漏掉前置动作 | 增加前置上下文；回归测试覆盖 caption 只记录结果的情况 |
| 细节回答继续复述粗粒度 caption | 定位后去掉 caption，只给原始画面和相关语音作为事实证据 |
| 相机视频接近容器 EOF 的抽帧为空 | 最后一帧避开名义末尾 250 毫秒；真实视频修复后完成处理 |
| 一次模型超时或格式错误导致整片重做 | 超时/限流最多重试一次；事件格式错误再校验一次；已完成窗口保存检查点 |
| 旧摘要/会话沿用旧识别 | 缓存版本与材料修订绑定，历史会话标记变化 |
| 分析入口隐蔽、失败文案与实际行为不一致 | 默认页可见分析按钮，失败给出可执行重试说明 |
| 密集帧导致同秒引用重复 | 正文相同时间范围去重，聊天同秒跳转按钮去重 |

## 配置与启动

不修改已有 `.env`。后端通过既有配置加载凭据，不向前端、日志或报告输出密钥。`.env.example` 仅提供公开配置示例。

| 配置 | 默认/建议 | 含义 |
| --- | --- | --- |
| `VISION_ENABLED` | `true` | 新视频默认分析画面 |
| `VISION_MODEL` | 建议 `qwen3.7-plus`；未设时回退 `LLM_MODEL` | 同一后端供应商的视觉模型 |
| `VISION_INTERVAL_SECONDS` | `0.5` | 窗口基础采样间隔；受帧预算约束 |
| `VISION_MAX_FRAMES` | `24` | 每次视频请求 4–24 帧 |
| `VISION_WINDOW_SECONDS` | `12` | 事件窗口长度，重叠 2 秒 |
| `VISION_SCENE_DETECTION` | `true` | 先按镜头分段，再处理长镜头 |
| `VISION_MAX_WINDOWS` | `180` | 模型调用前检查窗口总预算，超限明确报错 |
| `VISION_SHORT_VIDEO_SECONDS` | `90` | 全片原始画面概括路径的时长界线 |
| `WORKER_VIDEO_ID` | 默认不设置 | 设置后仅领取指定视频，用于限定测试范围 |

API 与 Worker 应使用相同视觉配置。Windows 可在启动二者的终端分别设置 `$env:VISION_MODEL='qwen3.7-plus'`，然后运行原有启动命令；这不会编辑 `.env`。FFmpeg、本地 ASR/嵌入模型及数据目录仍使用项目原有配置。普通运行不设置 `WORKER_VIDEO_ID`；本次代理测试的两个 Worker 分别限定两段已授权素材，不会处理其他上传。

镜头切分依赖位于后端 `ai` extra：`scenedetect-headless>=0.7.1,<0.8` 与 `opencv-python-headless>=4.12,<5`。不要同时安装普通版 `scenedetect`/`opencv-python`，它们共享模块文件。既有虚拟环境用 `pip install -e "backend[ai,dev]"` 更新后再运行 `pip check`；Docker AI 镜像会随项目依赖安装。没有重新构建或验证 Docker 镜像。

## 模型对照与质量边界

原有配置回退到 `qwen3.8-flash`；本轮最终 API 与 Worker 通过进程环境变量使用 `qwen3.7-plus`。对照保持同一个 DSCF0106 前 0–6 秒、同一组 24 帧、相同提示与参数，仅改变模型：

| 模型 | 单次请求耗时 | 结果 |
| --- | --- | --- |
| qwen3.8-flash | 4.17 秒 | 右手悬空、双手掰开；漏掉挥掌/拍击动作 |
| qwen3.7-plus | 10.80 秒 | 识别先向下劈砍或拍击、再向两侧掰开；对具体手法与是否预切保留不确定性 |

这是两次真实请求的小样对照，不是稳定准确率或延迟基准。Plus 的视觉支持与定位参照[官方模型说明](https://www.alibabacloud.com/help/en/model-studio/vision-model)。本次没有调用 Gemini，没有发送原始视频/音轨，没有训练或更换 ASR 模型。

Flash 完整流程基线已记录：西瓜 6 题与摘要均返回 200，但细动作及部分引用时间不准确；Sintel 一次概括出现校验失败，另一轮概括能识别预告片，但重复了“龙抓走女子”等不可靠事件描述，场景顺序问题有超时。因此 HTTP 200、引用和二次核验不能证明语义正确。

## 复现

1. 启动 API、Worker 和前端，使用同一数据目录和模型配置。上传支持的视频；旧视频从阅读页点击“开始音画分析”。
2. 观察任务经过 VISUALIZING、CHUNKING、INDEXING 到 READY；阅读页应显示新版事件数量。
3. 新建会话，询问主要内容，再用代词追问动作顺序、工具、事件时间，最后问视频不包含的姓名/预算。
4. 打开摘要，点击引用，确认视频当前时间与引用一致并能实际播放；刷新页面/重启 API 后检查事件、摘要和会话恢复。
5. 固定问题可用以下脚本记录。它只调用本地 API，不读取 `.env` 或素材文件；但后端可能发送抽样画面与转写至配置的外部模型并产生费用。应使用已获准素材。

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_video_workflow.py --video-id <UUID> --case-set camera --include-summary --output data\validation\camera.json
.\.venv\Scripts\python.exe scripts\evaluate_video_workflow.py --video-id <UUID> --case-set sintel --include-summary --output data\validation\sintel.json
```

每题记录 HTTP、耗时、答案、证据与空的 `manual_verdict`；需要人工对照原片填写，脚本不会按关键词伪造通过率。未来 10 段/60 题门槛仍需另行准备并标注素材。

## 最终验证记录

本轮以当前功能可交付为范围，不继续扩展模型调参。以下是实际观察，HTTP 成功不等于回答正确。

| 验证 | 结果 |
| --- | --- |
| 后端全量测试 | 150 项通过；覆盖窗口与短镜头、原始画面回看、缓存修订、旧会话、失败重试与 API 错误 |
| Ruff / Python 依赖 | `ruff check backend`、`pip check` 通过 |
| 前端测试 / 依赖 / 生产构建 | 7 个测试文件、28 项通过；`npm ls`、`npm run build` 通过 |
| 真实素材处理 | DSCF0106（30 秒）与 Sintel-trailer（52.208 秒）均到 READY；新版分别产生 9 与 26 个事件 |
| 最终真实 API 样本 | 两段视频各 6 个连续问题及 1 次摘要，共 14 次请求；13 次 HTTP 200，1 次 HTTP 503 `LLM_UNAVAILABLE` |
| 浏览器 | 实际验证分析入口、处理中禁用生成、状态刷新、新建会话、摘要和问答展示；检查时两测试页面无应用 JavaScript 错误 |
| 播放与引用 | 实际播放完成；点击西瓜问答引用后播放器时间约为 4.087 秒，媒体无错误；后端观察到视频 Range 的 206 响应 |
| 持久化 | API 重启后既有会话可恢复；事件、分析版本及摘要保存到本地数据库；旧材料会话提示与缓存更新有回归测试 |

原始真实上传已在前一轮完成；本轮是在这两条持久化视频记录上重新分析。相机 AVI 先转为 H.264/AAC MP4 后上传，不能据此声称浏览器原生支持该 AVI。固定问题的原始评测 JSON 保存在仓库外的本地测试目录，未把个人画面、转写或密钥放入 Git。

### 仍未关闭的风险

- 西瓜主题及分开两半的过程能识别，但最终一轮“怎么打开”的追问仍误拒答，挥掌动作不稳定；时间定位约在 3.7–4.0 秒，不代表动作解释完全正确。
- Sintel 最终能找到约 16.8–17.5 秒的战斗片段，改善了此前的漏检；但人物外观、武器、幼龙被称为红鸟等细节仍有误识别。摘要仍可能加入不准确细节。
- 姓名/地址、制作预算等无依据问题在两段视频中拒答正确。与此同时，真实有依据的问题也可能被核验器误拒；同一模型二次核验不是正确性保证。
- Sintel 的语音内容问题有一次供应商请求失败，返回可见的 503；其他轮次答出“寻找某个人”。不能报告为最终所有问题均通过。
- 语音仍使用原有 Whisper base；相机视频的嘈杂口语转写较差，未完成 ASR 模型对照。Windows 服务重启/视频请求取消时曾出现一次连接重置日志，服务随后正常；未证明该日志已消除。
- 尚未执行 10 段/60 题人工标注评测、长视频完整质量评估、Docker 镜像构建或公网后端负载测试；本报告不为这些项目背书。
