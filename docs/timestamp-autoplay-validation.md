# F-09 时间戳跳转后自动播放

2026-09-09；分支 `codex/timestamp-autoplay`，基于 `main` 的 `240d0a8`。

点击聊天证据时间戳后，播放器定位到对应时间并请求播放；转写、摘要与画面引用复用同一行为。初次打开阅读页只定位，不自动播放。暂停后重复点击同一时间戳仍会恢复播放。

元数据尚未加载时保留最新跳转目标，加载后应用；新跳转会取消旧目标和旧播放请求的错误回调。浏览器拒绝自动播放时显示可见提示，用户仍可点击播放按钮。拖动进度条不会强制把暂停状态改成播放。

## 验证

- 前端全量 33 项测试（8 个文件）及生产构建通过。新增测试覆盖初始不自动播放、跳转播放、重复时间戳、元数据延迟、浏览器拦截提示、过期请求失败和拖动进度条。
- 真实 Chrome 使用 FFmpeg 生成的 60 秒 MP4、隔离数据库及预置聊天证据，未调用模型，也未读取 `.env`。
- 页面初始状态：`currentTime=0`、`paused=true`、`muted=false`、`readyState=4`。
- 点击聊天证据（实际时间 4.5 秒）后：`currentTime` 从 4.802367 增加到 6.009309，`paused=false`，媒体无错误。
- 暂停后再次点击同一证据：从暂停状态恢复到 `currentTime=4.792704`、`paused=false`。
- 检查时无浏览器 JavaScript 错误。浏览器拦截回退通过模拟 `NotAllowedError` 的单元测试验证；未宣称跨浏览器自动播放策略均已实测。

## 复现

打开已有视频和包含证据的会话，暂停视频，点击回答下的时间戳。确认位置跳转、控制按钮变为“暂停”，播放进度持续前进；再次暂停并重复点击同一引用，应仍可播放。
