# ADR-002：FAISS + BM25 + RRF 混合检索

- 状态：接受
- 日期：2026-09-01
- 决策人：李乐妍（系统工程师）

## 决策

同一组带时间戳的转写分块建立 FAISS 语义索引与 BM25 词项索引。查询可经 LLM 扩展为最多 3 个变体；每路取 Top-8，采用 Reciprocal Rank Fusion（默认 k=60）融合、去重后向生成模型提供 Top-6。

## 理由

语义检索处理同义表达，BM25 保留人名、术语和数字等精确匹配；RRF 不要求不同分数空间可比，适合短周期 MVP。

## 质量约束

回答必须携带 `[mm:ss-mm:ss]` 引用；无足够证据时返回“视频中未找到依据”，不得脱离检索上下文编造。

## 2026-09-07：T12 实现澄清

- 总查询数最多 3：原始问题必保留，最多两条改写；按规范化文本精确去重。Qwen 关闭 thinking，使用 JSON 模式；失败仅退回原问题，不生成伪答案。
- RRF 的 rank 从 1 开始，每列表中同一 chunk_id 只投票一次。BM25 与向量分数绝不直接相加。小语料 BM25 分数可能为零或负值，按词项是否交集筛选，不把非正分数全部删除。
- 查询只读取数据库指向的一个已发布版本，并核对哈希、模型、维度、条数及视频分块映射。pickle 文件仅信任本地 Worker，校验值不提供反序列化安全保证。
- T12 不合并相邻分块，避免丢失原文与原始 chunk_id。上下文压缩、引用展示合并、token 预算和拒答属于 T13；RRF 分数不是答案置信度。
- 单视频 20 题开发集显示首位排序改善，但 Top-3 召回未全面胜过纯向量；不能以此证明通用质量。见 `evidence/t12-evaluation.json` 和 `t12-handoff.md`。保留三种模式便于独立后续评测，不对当前开发集过拟合调参。
