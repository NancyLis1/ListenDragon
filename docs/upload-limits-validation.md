# 上传时长校验修复

2026-09-09，分支 `codex/upload-duration-validation`。

## 行为

- `GET /api/v1/videos/upload-limits` 只返回 `max_upload_bytes`、`max_video_minutes`，不序列化应用配置。前端展示并使用这些值，同时消除写死 500 MB 的大小预检。
- 读取文件元数据期间暂停提交；严格超过时长上限才拦截，等于上限允许。更换文件时丢弃旧文件迟到的元数据结果。
- 浏览器读不到时长时，明确告知上传后由服务端校验。Worker 原有 FFprobe 校验仍为最终依据，超限时停止处理，不进入转写或视觉分析。
- `VIDEO_TOO_LONG` 显示“视频时长超限：最长支持 N 分钟”；失败步骤显示“视频时长校验 / 未通过”，上传步骤仍准确显示已完成。
- 限制获取失败时暂停上传并提供重试，不以任意默认值代替服务端配置。API 与 Worker 必须使用相同限制配置；更新配置后重启两者。

## 验证

- 后端 153 项测试、Ruff、`pip check` 通过。
- 前端 32 项测试（7 个文件）、`npm ls --depth=0`、生产构建通过。
- 新增覆盖：非默认限制值与公开字段白名单、等于/超过边界、开启视觉仍不能绕过 Worker 时长限制、迟到的旧文件元数据、元数据未知时后端拒绝、获取限制失败及重试。
- 独立 API 使用 1 分钟、2 MB 限制，不加载 `.env`、不调用模型。真实 Chrome 显示该配置。
- FFmpeg 生成 61 秒 H.264 MP4：浏览器读取到 1:01，显示时长超限，按钮禁用；后端视频列表仍为空，证明没有上传。
- 60 秒 H.264 MP4：浏览器允许继续；后端精确 60 分钟边界另有单元测试。
- 61 秒 MPEG-4 Part 2 MP4：浏览器无法读取时长，允许交给后端校验。实际上传返回 202、任务 QUEUED；运行一次真实 Worker 提取阶段，经 FFprobe 后返回 FAILED / VIDEO_TOO_LONG。浏览器轮询到失败并正确展示时长校验未通过；无应用 JavaScript 错误。
- 浏览器试验只验证此次限制与错误提示，不重复调用模型或宣称重新验证全部语义质量。生成的视频和临时数据库位于仓库外。

## 复现

1. API 与 Worker 使用相同 `MAX_VIDEO_MINUTES`，例如测试时设为 1；重启服务。保持生产配置原值即可，无须为修复修改上限。
2. 打开上传页，确认显示服务端实际最大时长和大小。
3. 分别选择 60 秒和 61 秒视频：前者可提交，后者显示超限且不能提交。
4. 对无法在浏览器读取元数据的合法视频，上传后等待 Worker 最终判断；超限时应显示“视频时长校验未通过”，不显示“提取音频失败”。

前后端需要一起更新：新前端连接旧 API 时缺少限制接口，会提示更新后端并暂停上传。问答框和其他成员的前端改动不在本次范围内。
